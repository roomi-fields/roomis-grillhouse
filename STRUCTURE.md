# Roomi's Grillhouse — structure

This is a complete project template for TypeScript and JavaScript (Node.js) development with best practices for Git, CI/CD, documentation, testing, and deployment.

## Directory Structure

```
roomis-grillhouse/
├── .claude/                    # Claude Code integrations
│   ├── settings.json              # Permissions, plugins (the frame's among them)
│   ├── template                   # Marks the template itself (not copied)
│
├── CLAUDE.md                   # The project's charter, filled by the initialisation grill; the common one comes from the frame's plugin
├── README.md                   # Describes Grillhouse itself (not copied to projects)
├── packages/grillhouse/         # The package @roomi-fields/grillhouse, a workspace: the frame's command, its scripts and its tests
│   ├── bin/grillhouse.mjs         # `grillhouse <sous-commande>` (`npx grillhouse` in a shell, `grillhouse` in an npm script): one subcommand per script a caller launches, named after it (`maj` for grillhouse-maj.mjs); an unknown one exits 2 with the list
│   ├── package.json               # its bin, its test:vitest (vitest run), what its tests read out of it (grillhouse.lit)
│   ├── vitest.config.ts           # the frame's tests of the day, extending @roomi-fields/grillhouse/vitest-config by its name
│   ├── turbo.json                 # generated by `npx grillhouse turbo-des-paquets --ecrire`
│   ├── scripts/
│   │   ├── init.mjs                   # npx @roomi-fields/grillhouse init <dir> [prefix]: a project from templates/projet/ (_gitignore, _npmignore renamed), the package declared, prepared (preparation.mjs), what maj writes, the generated files, one commit
│   │   ├── sortie.mjs                 # Grillhouse's release (CONTRIBUTING.md, §5): the package's package.json raised (the plugin takes its version when packed), CHANGELOG.md dated, then the tag v<version> on the release commit, locally, never pushed; --verifier-etiquette, which release.yml plays before publishing (Grillhouse only, not copied)
│   │   ├── preparation.mjs            # init's preparation: git, Beads and its store, CodeGraph and its index, Beads' hooks folder, npm install (whose prepare places the git hooks), then the frame's plugins (greffons.mjs), grillhouse@roomi-fields among them
│   │   ├── cadre.mjs                  # CADRE, where the package reads the template (its cadre/ installed, the repository otherwise), and GREFFON, the plugin's root with its METACADRE.md and consigne-agent.md (the package itself installed, mods/grillhouse/ otherwise); --empaqueter / --nettoyer, the package's prepack and postpack: the plugin copied at the package's root, its manifest at the package's version, the template under cadre/
│   │   ├── migrations.mjs             # MIGRATIONS, played by maj in the order of their versions, those newer than the project's grillhouse.version
│   │   ├── migrations/                # one module per change of form, <version>-<nom>.mjs, replayable without effect, each with tests/unit/migration.<nom>.spec.ts
│   │   ├── session-start.sh           # SessionStart hook: what is still empty (per package in the frame); the lock of the supervisor (superviseur.mjs); silent to a session of a role agent
│   │   ├── structure-guard.sh         # UserPromptSubmit hook: a structure decision goes to the grill; silent to a session of a role agent
│   │   ├── droits.mjs                 # The rights and the context of each role session the circuit launches, drawn from the commands its skill names: settings on the command line, the user's configuration out, its skills, tools and index servers alone, its locks (tests: tests/unit/droits.spec.ts)
│   │   ├── verrous/verrou.mjs         # The role agents' write locks (tests: tests/unit/verrous.spec.ts)
│   │   ├── verrous/commande.mjs       # The lock of the commands of a role that writes: no file of the repository written by the shell (tests: tests/unit/verrou-commande.spec.ts)
│   │   ├── verrous/ticket-du-sous-agent.mjs # hook: a role agent launches with « TON TICKET : <id> »
│   │   ├── enveloppe/                 # The envelope: an agent sees its component, the others' interfaces, the test material, what its tests declare they read
│   │   │   ├── enveloppe.mjs             # bwrap sandbox for one component (tests: tests/unit/enveloppe*.spec.ts)
│   │   │   ├── codes.mjs                 # the exit codes of the envelope and its launcher
│   │   │   ├── composant.mjs             # GRILLHOUSE_ENVELOPPE, the component the envelope names: npm test and npm run api build and write it alone
│   │   │   └── lancer.sh                 # one ticket → one fresh role session in its envelope, its providers and the traces its tests read produced first, its instruction followed by what its providers publish; each session added to the ticket's log under its header line, its exit code in .claude/worktrees/<ticket>.fin
│   │   ├── circuit.mjs                # the circuit of one ticket, component by component in the order of its title: testwriter, proof of the red (the lot's tests played, a green justified by an expected green of the testwriter's sheet), developpeur, checks (what is done up to the component, guards in its envelope; after the last one the final pass, a red sent to the developpeur of the component that owns it), then the reviewer out of the envelope (RENDU: the agent each finding of its sheet names plays again, three reviews at most), then on ACCEPTÉ the integration (the lot built from the copy, integrer.mjs), then the queue, and ends on the state of the ticket it leaves; decides on structured results alone (scripts/resultats.mjs: each session's sheet, Turborepo's summaries, Vitest's JSON reports, the guards' SARIF); writes each instruction from consigne-agent.md, stops a session whose transcript stands still 20 min, resumes a session without a sheet once; state in .claude/worktrees/<ticket>.circuit.json, working directory .claude/worktrees/<ticket>.travail (the ticket's: taken up again by a relaunch, removed by the queue at the closure or with the copy), one comment « Circuit · … » per step, --reprendre, --depuis <testwriter|developpeur> <component> for a lot corrected by one component; on a stop other than 0 and 75 it launches the regulator's session itself and applies its decision (RELANCE, or MONTE: the stop « question », the session kept, --reponse pours the answer into the plan, then resumes it; --decision pours an owner's decision given out of any question into the plan, the circuit running on the ticket stopped first, then resumes where it was, the components the change reaches played again); before the first testwriter, and on each decision of the regulator before it applies, the questionneur's rounds with the author (the technical referent for the plan, its changes written to the ticket by the circuit; the regulator in its own session), four at most, the exchange at the ticket, the stop « questionnement » (22) for a plan that does not converge
│   │   ├── etapes.mjs                 # the tree of the steps of a ticket, 0 to 5 and their sub-steps, the « auto » ones included: number, title, who works there, per component or once, the bounded loops each step carries; the arbitrage of a stop, out of the sequence; the stops of the circuit and their codes, the table of the stops; the circuit, the board, the bilan and the tests read it
│   │   ├── avancement.mjs             # the progress of an automatic pass (GRILLHOUSE_AVANCEMENT): its tasks' files done and planned added, a task replayed from the cache counted done, the total of the previous pass of its kind (<git common dir>/grillhouse/avancement.json); a measure out of a ticket named beside the lock of the machine; read by the board
│   │   ├── dernier-vert.mjs           # the last green of each branch (<git common dir>/grillhouse/dernier-vert/<branche>.json: HEAD and the tree of the working tree of the last pass green; a copy without one measures against main's), the files changed since it, which verifier and npm test under the circuit's mark measure against
│   │   ├── dette.mjs                  # the known debt of the guards: grillhouse-dette.json (guard, file, rule → count); a guard passes within the counts, refuses a new finding or a count beyond, reports a count below
│   │   ├── composants-affectes.mjs    # the components a ticket touches: for each element its Architecture and criteria name, its provider (an INTERFACE.md) and readers (declared consumers, importers, other packages' tests naming it), its readers by the types (references-par-les-types.mjs), the packages whose grillhouse.lit covers a path the ticket changes, and the Rend of the CADRE.md of the packages that publish the elements, a package that carries a type never a reader; the explorateur's survey, the circuit's check before the first testwriter
│   │   ├── references-par-les-types.mjs # the references of a ticket's elements by TypeScript's language service: a symbol or a member resolved, the references of one its package's entry exports in the other packages; an internal one has no readers out of its package
│   │   ├── code-mort.mjs              # grillhouse:gardes: refuses dead code, measured by knip (knip.json); tests and benches count for dependency use only
│   │   ├── consommateurs.mjs          # grillhouse:gardes: refuses an import that the provider's INTERFACE.md does not declare, and two components of the same name
│   │   │                              #   composants(): the components for every check, minus the packages out of
│   │   │                              #   the frame listed in docs/agents/hors-cadre.txt, "<package> <reason>"; such a package stays a
│   │   │                              #   workspace, and Turborepo plays none of its tasks (turbo-des-paquets.mjs)
│   │   │                              #   parcourir(): the walk of every guard, Vite's temporary files left out, a file gone meanwhile passed over
│   │   ├── consommateurs-arbitres.mjs # grillhouse:gardes: a Consommateurs line a lot changes enters with a settled arbitrage at its ticket naming the consumer, or named, consumer and names, by the ticket's Architecture
│   │   ├── crochet.mjs                # grillhouse hook <nom>: the guard of one frame git hook, which the hook calls (nothing without the package)
│   │   ├── crochets.mjs               # grillhouse hooks: the frame's git hooks (commit-msg, pre-push), Husky's model: placed by the project's prepare and grillhouse:maj beside Beads' sections, a former version's lines rewritten, absent ones named by the session start
│   │   ├── greffons.mjs               # the frame's plugins (those `.claude/settings.json` enables): installed for the project by preparation.mjs (init) and grillhouse:maj; absent ones named by the session start, and the frame's plugin installed at another version than the package, with the command that aligns them
│   │   ├── gardes-du-cadre.mjs        # npm run grillhouse:gardes: the frame's guards, the one list of them (GARDES_DU_CADRE), each played whatever the verdict of the ones before; each red named, code 1 when one is red
│   │   ├── frontieres.mjs             # grillhouse:gardes: dependency-cruiser (after the build, which it reads), rules generated in .dependency-cruiser.cjs
│   │   ├── interfaces-contre-code.mjs # grillhouse:gardes: the TSDoc contract of each export (rubrics, tsdoc.json) and the generated part
│   │   │                              #   of INTERFACE.md between its two marks; npm run api writes the reports and the parts
│   │   │                              #   (a package without a « . » export, the shared test material, has no API to check)
│   │   │                              #   (in an envelope, its component alone: tests/unit/commandes-en-enveloppe.spec.ts)
│   │   ├── resultats.mjs              # the one module of the formats of results the circuit decides on: the sheet of each role (its JSON schema, --schema <rôle>; read in claude's structured_output), the guards' SARIF 2.1.0 (ecrireSarif, under GRILLHOUSE_RESULTATS, which a project's guards use too), Turborepo's summaries and Vitest's JSON reports
│   │   ├── resumes.mjs                # grillhouse:gardes: the first sentence of each published element's summary holds in 80 characters, refused at its INTERFACE.md § element
│   │   ├── nuit.sh                    # once a night, the full pass played for real (npm run verifier -- --force: Turborepo's build, guards and tests, no log replayed), then the night tests and budget benches, then the project's night script (`grillhouse.nuit`), and pushes the green commit (`grillhouse.poussee.nuit`); a red night's ticket gives the commits since the last green and, for each red task verifier names (GRILLHOUSE_ROUGES), its `git bisect run` command
│   │   │                              #   (*.nuit.test.*, *.nuit.spec.*, *.budget.test.*, *.budget.spec.*); a red opens a ticket;
│   │   │                              #   « à repasser » (75: benches played once more at rest, then still under load) opens nothing and keeps the last green
│   │   ├── vitest-config/             # the base configuration the package exports as @roomi-fields/grillhouse/vitest-config (and ./mesure, each typed by its .d.ts): the frame's base Vitest configuration of the day, which every day configuration extends (mergeConfig): night tests and budget benches excluded, the common environment, the one address of git's settings for the suite (automatic maintenance off), the plugin that restricts a run to the tests GRILLHOUSE_TESTS names (cibles.mjs)
│   │   │                              #   the measure of time at rest: pression.mjs (the CPU pressure, /proc/pressure/cpu some avg10, threshold 25 %, code 75; `attendre`), mesure.setup.mjs (the pressure noted at the start and end of each test),
│   │   │                              #   duree.reporter.mjs (75, « à repasser », when every failure depends on a duration and one took place under load), mesure.mjs (mesurerAuRepos, the mark of a measure of time; a file that imports it is a time witness, which verifier plays alone),
│   │   │                              #   machine.setup.mjs (each test file a lock of the heavy measure of its own),
│   │   │                              #   base-de-passe.mjs (the base of a pass, `grillhouse-<genre>-XXXXXX/t` named in TMPDIR, removed at its end, the orphans of a killed pass swept: each run of Vitest by its plugin, npm test, npm run verifier, the passes of a circuit's run, an integration, an envelope),
│   │   │                              #   resultats.setup.mjs (each test file's processes a results directory of their own, under GRILLHOUSE_RESULTATS/essais/, which no reader reads),
│   │   │                              #   resultats.mjs (the JSON report of Vitest written under GRILLHOUSE_RESULTATS, which scripts/resultats.mjs reads)
│   │   │                              #   changements.mjs (the changes since the last green, GRILLHOUSE_CHANGEMENTS: the tests Vitest relates to them, or the whole package when one lies out of Vitest's graph, the reason written)
│   │   │                              #   avancement.mjs, avancement.reporter.mjs (under GRILLHOUSE_AVANCEMENT, the files done and planned of each task, written at each test file done, which scripts/avancement.mjs reads)
│   │   │                              #   every configuration of a project imports it by its name; each tested package of a repository of packages declares the frame's package, which grillhouse-maj writes
│   │   ├── vitest.nuit.config.mjs     # the Vitest configuration of the night tests, played by nuit.sh; git's settings, its setup file and its duration reporter read from vitest-config/base.mjs
│   │   ├── sous-modules.sh            # the submodules of a working copy (integration, agent, night) at HEAD, or shared read-only (grillhouse.partage)
│   │   ├── branche-de-nuit.mjs        # pre-push guard: only the night pushes the branch of grillhouse.poussee.nuit
│   │   ├── poussee-cles.mjs           # reads the grillhouse.poussee, .nuit and .commit keys of package.json for nuit.sh, the guard and the queue
│   │   ├── retirer-copie.sh           # removes a working copy, submodules included (local work already entered on main does not hold it), with the working directory of its ticket's circuit, <copie>.travail (--garder-travail: the integration's, which the queue removes at the closure) (agent, integration, night)
│   │   ├── grillhouse-maj.mjs         # npm run grillhouse:maj: the project brought to the version of the package installed, as @turbo/codemod migrate: the migrations newer than its grillhouse.version, then what the frame writes, read in the package's template (scripts, prepare, turbo.json when absent, the tools the checks run, packageManager, .turbo/ ignored, the frame's package declared in each tested package, the status line of .claude/settings.json, git hooks), the generated files regenerated by the project's command, the plugins installed; the version recorded and named in the report; any argument refused
│   │   ├── turbo-des-paquets.mjs      # grillhouse:gardes: refuses a package's turbo.json absent or stale, and a guard task of the root's turbo.json (grillhouse:gardes, gardes) absent or whose dependsOn is not the build of each package of the frame, and a root test:vitest whose env lacks GRILLHOUSE_TESTS (the variable of the targeted runs); --ecrire writes them (a package's extends the root's, its build waits for the build of its runtime dependencies only: dependencies, peerDependencies, optionalDependencies; its test:vitest hashes the paths (directories or files, data or a neighbour's code) its package.json declares, `grillhouse.lit`, and waits for the traces that write them; each trace it declares, `grillhouse.traces`, is a cached task writing a directory of the package git ignores; the build of the package holding a declared path of data alone leaves it out, a path holding code stays in; a build with a tsconfig.build.json hashes what it reads, its package.json, its configurations and the directories they include, when its build script runs tsc alone, else every file of its package; beside each input reaching the `.git` of a submodule of .gitmodules, in the root's turbo.json and a package's, its exclusion `!<path>/.git`; the root's guards' dependsOn by jsonc-parser, the rest of the file kept); it refuses a declared path absent that no trace writes, a trace out of its package, followed or not ignored by git, a trace script and its declaration apart, and in the root's turbo.json a task of one package, a trace task or an input naming a package directory
│   │   │                              #   a package of docs/agents/hors-cadre.txt has each task of the root excluded ("extends": false), and no dependsOn written names it
│   │   ├── paquets.mjs                # paquets(): the frame's one list of the packages, the workspaces mapped as npm maps them (a « ! » pattern takes out), each marked out of the frame or not (horsCadre(): the names docs/agents/hors-cadre.txt lists, which every check reads);
│   │   │                              #   read by grillhouse-maj, turbo-des-paquets and tests
│   │   ├── tests.mjs                  # npm test, npm run test:forcer: turbo run test:vitest; each path named from the root plays in the package that holds it (--filter, the path made absolute), a path out of the frame's packages refused;
│   │   │                              #   a run with paths is one run of the tests with what they depend on, the paths and options in GRILLHOUSE_TESTS (the env of test:vitest: in the hash of the tests alone), the builds and traces replayed from the cache;
│   │   │                              #   --force puts the moment of the run in the variable (the tests alone played for real); in an envelope, its own package's build and traces (--only), then the tests alone (--only), whose hash sees no neighbour's code
│   │   ├── verifier.mjs               # npm run verifier, under the lock of the machine: turbo run grillhouse:gardes gardes test:vitest --continue=dependencies-successful --concurrency=<half the cores> --summarize, the time witnesses left out,
│   │   │                              #   then the witnesses alone (--concurrency=1, one file at a time); the code of each task read in the summary (removed after):
│   │   │                              #   any code but 0 and 75 is red, named; a task at 75 waits for rest (15 min at most) and plays again (--filter, its dependencies from the cache); the bound reached, 75 « à repasser »
│   │   │                              #   measured against the last green (dernier-vert.mjs); --tout and --force the complete pass, every test for real
│   │   ├── verrou-de-machine.mjs      # the lock of the machine for the heavy measure (~/.cache/grillhouse/mesure-lourde.lock), shared by every repository: taken by verifier.mjs and the heavy passes of circuit.mjs
│   │   │                              #   the wait said every 30 s with its holder, bounded at 60 min (75); a lock held by an ancestor stops at once, red
│   │   ├── superviseur.mjs            # one supervisor per project: the session start takes the lock of the repository; a second session is told who holds it
│   │   ├── tableau.mjs                # npm run tableau: the board on three levels (project, agents, chantier)
│   │   ├── ligne-etat/                # the status line: the person's own on the left, the chantier on the right
│   │   ├── verrou-de-fichier.mjs      # the lock of a file shared between processes (judged by the owner's process or by age); taken by integrer.mjs, file.mjs, registre.mjs, verrou-de-machine.mjs and superviseur.mjs
│   │   ├── registre.mjs               # hook: one line per finished agent (ticket, role, time, tokens)
│   │   ├── bilan.mjs                  # the bilan of a ticket, written by the circuit at each end: wall time by category (work kept, relaunch without effect, questioning, wait, automatic steps, final passes, replay, between steps), the sessions the circuit launched and the supervisor's apart, stops, tokens, cost, against the project's bilan before
│   │   ├── integration/               # One delivery, in a clean copy: verdicts, lots, npm run verifier green, commit on agent/<ticket>; then the queue brings it onto main
│   │   │   ├── integrer.mjs              # run by the circuit on ACCEPTÉ: commits the lot on agent/<ticket>, labels the ticket en-file, puts the branch in the queue (tests: tests/unit/integrer*.spec.ts)
│   │   │   ├── file.mjs                  # the queue: brings the branches onto main one at a time, replaced and replayed when main moved, pushes main, then reads the CI of the commit pushed (gh: a red CI reopens the ticket; no workflow that runs on a push to the branch pushed, none waited for, the ticket told in one line) (tests: tests/unit/file-integration*.spec.ts)
│   │   │   ├── rejeu.mjs                 # the replay shared by integrer.mjs and file.mjs: clean copy, dependencies of its lock file, npm run verifier (Turborepo: build, then guards and tests); a 75 keeps the lot waiting
│   │   │   └── file-attente.mjs          # the queue's entries (a branch and its one ticket each), in git's common directory, and the directory the integration's locks live in
│   │   ├── index-interfaces.mjs       # npm run interfaces: docs/agents/index-des-interfaces.md from the generated parts, checked by grillhouse:gardes; --publie <composant>: what its providers publish (each provider's line, the names of the elements declared for it, the address of its CADRE.md « Rend »), for the launcher
│   │   └── un-commit-par-ticket.mjs   # commit-msg hook (grillhouse hook commit-msg, crochets.mjs): a closed ticket refuses a second commit, a reopened ticket takes its corrections
│   └── tests/                     # The frame's tests (unit/) and their material (claude-substitut, config-git, machine, unit/*-essai.ts): Grillhouse only, not copied
```

## Quick Start

### 1. Create the project

```bash
npx @roomi-fields/grillhouse init ~/dev/my-new-project [ticket-prefix]
```

Copies the template of a project (`templates/projet/`), declares the frame's package,
initialises git and the Beads ticket store, installs the dependencies, and makes the first
commit. The project keeps the example application (`src/`) and its tests
(`tests/unit/config.spec.ts`, `errors.spec.ts`, `types.spec.ts`), which its `npm test` plays.

Prerequisites: Node.js and Claude Code. Everything else installs by default: `init` installs
Beads (`bd`) when missing, and installs, for the project, the Claude Code plugins the project
settings enable: `mattpocock-skills` (grill, TDD, code review, handoff), `rtfm` (search index) and
`grillhouse` (the frame's skills, agents, hooks and common charter, and the board). `grillhouse:maj` installs them too, and a session start names under
« Manque » each one still missing.

### 2. Open Claude Code in it

The first session sees that the project is not initialised yet (SessionStart hook) and proposes
the **initialisation grill** (skill `grill`). The grill settles, round by round: the project,
its owner, what decides, library or service, the components and their frame, the interfaces, the
architecture, the lexicon, the first chantier. Then it writes `CLAUDE.md`, `docs/ARCHITECTURE.md`,
`docs/CADRE.md`, `docs/INTERFACE.md`, `CONTEXT.md`, the package identity, and opens the first
tickets. Once done, the hook stays silent.

### 3. Work

- A supervision session loads `pitmaster`: it keeps the tickets and launches the circuit of each
  one.
- The roles are agents of the frame's plugin (`mods/grillhouse/agents/`): `testwriter` writes the tests, `developpeur` the
  code, `relecteur` reviews; the circuit of the ticket (`npx grillhouse circuit`), which the
  supervisor launches, launches them and commits, and on a stop launches `regulateur`,
  which settles it in its final answer; `questionneur` questions the ticket's plan before the
  first testwriter and each decision of the regulator before it applies, its author answering in its
  own session. Each loads its skill
  and works under its locks.

### An existing project

Install the frame's package (`npm install -D @roomi-fields/grillhouse`), run `npx grillhouse maj`, open Claude Code: the
`grill` grill describes the existing construction from the code and asks only what the code
does not settle.

## JavaScript Projects

The template accepts `.js`/`.mjs` alongside `.ts`, so a JavaScript project can adopt it
as is and migrate to TypeScript file by file:

- `tsconfig.json` sets `allowJs` (JS compiles to `dist/` with the TS) and `checkJs: false`
  (no type errors on untyped JS; enable it to start typing through JSDoc).
- ESLint applies the shared rules to every file; the TypeScript parser and type-aware rules
  apply to `.ts` only.
- Vitest, Prettier and coverage match `.ts`, `.js` and `.mjs`.
- Tests are written with Vitest (`describe`/`it`/`expect`, or `node:assert` inside `it`).
- A library consumed straight from `src/` needs no build: drop the `build` script and the
  CI skips it (`npm run build --if-present`).

Migrating to TypeScript: rename a file `.js` → `.ts`, add types, keep the `.js` import
specifiers (Node16 resolution), run `npm run typecheck`.

### Service vs Library

`deployment/`, `ecosystem.config.cjs`, `logs/`, `.env.example` and the `daemon:*` scripts
serve long-running services. A library leaves them out.

## Customization Guide

### Adding Dependencies

```bash
# Runtime dependency
npm install package-name

# Dev dependency
npm install -D package-name
```

### Adding npm Scripts

Edit `package.json`:

```json
{
  "scripts": {
    "custom": "your-command"
  }
}
```

### Adding GitHub Actions

Create `.github/workflows/your-workflow.yml`

### Adding Claude Skills

A skill of the frame goes to its plugin, `mods/grillhouse/skills/`; a skill of the project alone:

1. Create `.claude/skills/skill-name/SKILL.md`
2. Add YAML frontmatter with name and description
3. Write skill instructions in Markdown

### Adding Test Files

Place tests in:

- `tests/unit/` for unit tests
- `tests/integration/` for integration tests

Use the `.spec.ts` (or `.spec.js`) suffix.

## Maintenance

### Updating Dependencies

```bash
# Check outdated
npm outdated

# Update all
npm update

# Update specific
npm install package@latest
```

### Version Release

Use the release skill or:

```bash
npm version patch  # or minor, major
git push origin main --tags
```

Grillhouse itself releases with `npx grillhouse sortie`, which no project receives: one version for the package and its mod, the `version` of `packages/grillhouse/package.json`, which the push of its tag publishes on npm (`CONTRIBUTING.md`, §5).
